## Stream badge appearance and FR-Badges

Settings → Sources & library → Stream badges → *Stream badge appearance*:
Riwaq default (unchanged, the default), Liquid Glass (local CSS), FR Glass,
FR Frost, Minimal (FR-Badges by farizmohd70, MIT), or none (`badgesOn`).

- What is supported: FR-Badges' **Lite** files, 219 badges per style, read
  from `badges.json`, `badges-frost.json`, `badges-minimal.json` at
  `raw.githubusercontent.com/farizmohd70/FR-Badges/main/`. Inspected here
  as data: 14 groups, every pattern written with Java's `(?i)` and some
  lookbehinds; Riwaq's importer already reads them (195 rules + 24
  pictures for built-in chips, none skipped). Groups are now kept on rules.
- Original pictures vs local fallback: FR pictures are **addresses**; they
  load from GitHub when sources show. Nothing from FR-Badges is bundled.
  A picture that fails (offline, blocked) shows its badge's name as a
  Liquid Glass chip (FR sets its colours fully transparent, so the old
  fallback would have been invisible).
- Not supported: the full 732-badge library (more than the 250 rules a
  profile keeps), and FR's other eleven styles (their files exist upstream;
  adding one is a line in `FR_STYLES`).
- Rows keep the viewer's own badges first, then quality, HDR, audio,
  source, languages; a badge that says what a built-in chip says replaces
  it; the rest fold behind "+N" with their names in the tooltip.

## Liquid Glass

`src/liquid.css` builds one chip, one panel and one badge on the existing
`--glass-*` tokens of `src/glass.css`, so Solid, reduced transparency,
forced colours, browsers without backdrop-filter and the light scheme all
follow from one place. No backdrop blur on chips, badges or cards; over
pictures (collection cards, the player bar) the fill stays dark in both
schemes and text is white. It is used by the source filters, the stream
badges, the collection cards and tools, the templates, the folder editor
and the import preview; the player bar's chips (`src/player-bar.css`) use
the same recipe with their own over-video values.

## Collections

- **Model** (`core/collections.mjs`): folders keep `cover` (still), `gif`,
  `gifOn`, `backdrop`, `logo`, `glow`, `hideTitle`, `shape`; collections a
  `logo`. Only what is set is stored. `artUrl` accepts HTTPS images and
  `local:<32 hex>`; a `.gifv` or video address is refused.
- **Moving covers** (`src/components/CollectionArt.jsx`): the still first;
  the GIF only while that card is hovered or focused, only after it has
  loaded; unmounted on leave; a failed GIF falls back to the still for the
  session; reduced motion never starts one; no picture → the theme's
  placeholder. Proven in Chromium by request counting (no GIF request
  before hover).
- **Local pictures** (`core/collection-art.mjs`, `electron/collection-art.mjs`,
  `web/collection-art.js`): the bytes decide (GIF/PNG/JPEG/WebP, 8 MB,
  4096 px); random ID; `userData/collection-art` or IndexedDB; the page
  gets a data URL or object URL, never a path; unreferenced files are swept
  after a 10-minute grace. They never travel in backups, accounts or Nuvio
  exports. **Desktop path not run here** (no Electron); the file backend is
  unit-tested on the real filesystem.
- **Nuvio** (`fromNuvio`/`toNuvio`): every display field both ways,
  `tileShape` written as Nuvio does (`LANDSCAPE`), unread sources kept as
  plain data and exported back, Riwaq's exported IDs stay stable (they used
  to gain another `nuvio-` prefix, so re-importing an export duplicated).
  Report: readable sources, unread ones by folder, what went past each
  limit. Paste flow: preview → choose collections → merge (by ID, folder
  by folder) / add copies / replace all → report. Limits unchanged (60 /
  100 / 40 per kind / 500 titles): a 70×120×50 fixture imports in about a
  second and reports 10 collections, 1,200 folders and 60,000 sources that
  did not fit. A paste is limited to 4 MB as before.
- **Templates** (`core/collection-presets.mjs`): World cinema (Arabic by
  language; 11 countries/regions by origin country), Reality TV (genre
  10764), Kids & family, Documentaries, Based on, Moods & vibes, Spotlight
  (the studio/network IDs Riwaq already ships), and one Mega collection.
  All TMDB discover queries, editable, needing the viewer's TMDB key.
  "New" rows use `recentDays`, counted from the day of the request.
  **Unverified here:** the four "Based on" keyword IDs (818, 9672, 9717,
  41645) come from community configurations; TMDB was unreachable from
  this environment, so they are shown in each row's title for checking.
  Not copies of Kaptain's folders, lists or artwork (none was available).
