## Additional defects fixed in this review

1. **Late TorrServer launch after Stop.** On the original #87, pausing verification, calling Stop and then completing verification still called launch once. It now calls it zero times. A host generation invalidates obsolete verification, echo/authentication and settings restarts; one retired process cannot tear down a newer one.
2. **Cancelled metadata preparation lingered.** PlaybackRequest now provides an abort signal. TorrServer API reads and polling observe it, return their own lease and allow idle shutdown. A cancelled sole start also revokes the pending program launch. A real unavailable-torrent cancellation was checked on Windows.
3. **A stale fallback could start after Stop/new user pick.** The old chain now verifies viewing/request ownership before and after reading its file list. Only the current failed attempt may advance to the next source; a stopped or superseded attempt may not.
4. **Duplicate episode basenames chose the wrong season.** Original #87 chose file 1 for both `Episode1.mkv` and `Season2/Episode1.mkv`. Both engines now preserve the bounded relative path hint, match exactly or uniquely, and refuse an ambiguous or missing explicit filename instead of guessing another episode. A valid addon index still takes precedence. Both real engines were checked with duplicate basenames in separate season folders.
